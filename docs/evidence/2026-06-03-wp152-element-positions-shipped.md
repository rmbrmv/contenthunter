# WP#152 — позиции элементов схем 35-70 (только верхние углы): SHIPPED+DEPLOYED 2026-06-03

## Проблема (фидбэк Анастасии, OP#152 03.06 11:58)

> схемы 35-70 лого слева, а не справа и местами на оверлэй попадает, но в 65,60,57,48,45,36 оверлей справа и они не пересекаются …

Два дефекта: (1) лого клиента в левом верхнем углу вместо правого; (2) местами лого налезает на оверлей-лицо.

## Корень

`logo_position` = NULL у всех схем 35-70 (генератор `gen_wp152_schemes.py` его не выставлял). Воркер: `scheme.get('logo_position','top_right')` — при значении NULL ключ существует со значением None, поэтому default НЕ подставляется → `_xy(None)` падает в запасную ветку `(ox,oy)` = левый верхний угол. У старых схем 1-34 `logo_position='top_right'` задан явно. Тот же класс бага `dict.get(k,default)`-vs-None, что в триаже пустых превью (3-й раз в пайплайне).

## Решение

**Правило (Данил):** лицо (аватарка-оверлей) и лого — только в двух разных ВЕРХНИХ углах, лого напротив лица. Низ и центр запрещены (субтитры исходных роликов + элементы интерфейса приложений перекрываются).

Источник истины — `element_positions(sid)` (`unic-worker/scripts/wp152_element_positions.py`):
- FACE_TOP_RIGHT = {36,38,41,43,45,48,50,52,53,55,57,60,62,65,67,69} → лицо top_right / лого top_left (16 схем)
- остальные 35-70 → лицо top_left / лого top_right (20 схем)
- logo_offset = 20/20

«Хорошие» схемы Анастасии (36,45,48,57,60,65 и др.) визуально не изменились — у них уже было лицо top_right + лого top_left, лишь закрепили явно.
