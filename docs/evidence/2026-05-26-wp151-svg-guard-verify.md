## Что проверял

Смоук на синтетическом ассете «SVG, замаскированный под `.png`» — точный кейс #151.
Скрипт: `/tmp/smoke_151.py` (ad-hoc, не в репе).

| # | Проверка | Ожидание | Факт |
|---|----------|----------|------|
| 1 | Детекция SVG под именем `.png` | True | `looks_like_svg=True` (`<svg xml`) |
| 2 | Прод-симптом до гарда (форс PNG-декодера) | провал | `Invalid PNG signature 0x3C73766720786D6C`, ffmpeg rc=69 |
| 3 | Гард растеризует SVG → PNG | конвертация | `converted=True`, сигнатура `\x89PNG`, 1024×1024 |
| 4 | Тот же FFmpeg-декодер после гарда | успех | rc=0, codec=png |
| 5 | Kill-switch `UNIC_SVG_RASTERIZE_ENABLED=0` | no-op | файл остался SVG |

Прод-симптом воспроизводится только при форсированном PNG-декодере
(`ffmpeg -vcodec png`): у локального FFmpeg-билда есть SVG-декодер (librsvg), и при
авто-пробинге он съедает SVG напрямую. В проде в дело шёл именно PNG-декодер
(лог `Invalid PNG signature 0x3C73766720776964` = `<svg wid`), поэтому форс PNG —
верное воспроизведение. Гард делает поведение детерминированным независимо от билда:
до FFmpeg ассет гарантированно настоящий PNG.

## Вывод

сломанный файл больше не роняет конвейер, есть kill-switch для отката. Задача
подтверждена закрытой. По #151 не осталось работы; реальная выкладка Anecole зависит
от #150 (аккаунты) и трекается в #149.
