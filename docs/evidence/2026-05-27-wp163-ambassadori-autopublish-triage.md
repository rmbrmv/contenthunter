# WP #163 — Ambassadori: почему авто-публикация падала (триаж)

**Дата:** 2026-05-27. **Тип:** discovery/триаж (read-only, без правок авто-тракта). **Подход:** B (агрегат по `meta.category` + deep-dive screencast/dump). **БД:** openclaw (прод). **Проект:** Ambassadori = `validator_projects.id 58`, авто-эра слотов 14.05–29.05.

Методология: первопричина = последний `events[].type='error'` → `meta.category`; `error_code` игнорируется (фиксирует первую/preflight-ошибку). Из «последней значимой» ошибки исключён teardown-шум (`screencast_stop_failed`, `screencast_pull_failed`, `device_artifacts_cleanup`, `process_interrupted`) — он маскировал реальные причины (на YT вскрыл +4 `yt_create_menu_not_reached` и +6 `yt_editor_not_reached`). Транзиент-инфра (`adb_*`) учтён отдельно.

## TL;DR

1. **Главная стойкая причина — TikTok: обрезка длинных юзернеймов в свитчере аккаунтов → `tt_account_not_in_list`.** TikTok режет длинные имена (по ширине, ~17 символов, без многоточия) в боттомшите выбора аккаунта; матчер `find_account_in_list` сравнивает **точным равенством** нормализованных имён (в отличие от YT, где есть fuzzy-prefix). Длинные Dubai-имена Ambassadori (`golden.square.dubai` 19, `yield.dubai.estates` 19, `dubai_asset_expert` 18) систематически не матчатся, **хотя аккаунты привязаны к устройству** (подтверждено в `sa_preflight.known`). Причина активна и рецидивирует (25.05). **Подтверждено тремя линиями: UI-дамп + код + корреляция длины имени.**
2. **Instagram — своей причины нет.** Доминанта IG — флитовый инфра-сбой 15.05 (`adb_devices_unreachable`, 100% fail на всех платформах в этот день) + мелкий продуктовый хвост (по 1). После 20.05 IG здоров (0–14%).
3. **YouTube — уже восстановился.** Провал 15–20.05 (`yt_create_menu_not_reached` 14, `yt_editor_not_reached` 12) к 21.05 спал до 0–20%; отработали отгруженные YT-гарды (#87/#113/#132/#134). Новых действий не требует.
4. **Премиса «массовый прогон 22.05» — опровергнута.** 22.05 был лёгким днём (7 падений); 0 событий `retry_clean_slate` у Ambassadori; движок ретраев проект массово не пере-прогонял. Пики падений — 15.05 (инфра) и 19.05 (YT). «22.05» — это дата системного «чистого листа» движка (#108), а не объём Ambassadori.
5. **Премиса «переведён на ручную 25.05» — данными не подтверждается.** Проект продолжал авто-публиковаться после 25.05 (23 `done`-слота с авто-задачей, 0 ручных handoff). Флаг `manual_publish` сейчас **FALSE** (= авто), последний раз менялся **сегодня 27.05 07:42 UTC**.
6. **Ambassadori — НЕ выброс по fail-rate.** Весь флот в этом окне сыпался сопоставимо/хуже (ClickPay 50/68/71, Relisme 72/71/68 и т.д.); YT высок почти у всех.

## Deep-dive: TikTok `tt_account_not_in_list` (главная причина)

**Кейс task 9613** (25.05, аккаунт `golden.square.dubai`, устр. RF8YA09SMBJ):

- `sa_preflight.known = ["golden.square.dubai", "yield.dubai.estates", "luxurybitesdubai"]` — **целевой аккаунт зарегистрирован на устройстве**.
- Свитчер открыл боттомшит (`tt_probe_opened_bottomsheet: sheet_open_signal=true`), снял UI-дамп `tt_3_pick_account` (читаемый, 14 КБ, заголовок «Сменить аккаунт»), но аккаунт не нашёл → `error tt_account_not_in_list` (`resolved_from: switcher_fail_event`).
- **В дампе строки списка обрезаны:** `golden.square.dub` (из 19 симв.), `yield.dubai.estat` (из 19), а `luxurybitesdubai` (16) — целиком. Обрезка **жёсткая, без многоточия** (сырые байты заканчиваются на `dub"`). Дамп: `…/ui_dumps/tiktok/task9613_switch_9613_tt_3_pick_account_1779694228.xml`.

**Код** (`account_switcher.py`): `_find_and_tap_account` (шаг `tt_3_pick_account`) → `find_account_in_list(elements, target)` → матч `AccountSwitcher._normalize_username(tok) == t`, где `_normalize_username` = `strip().lstrip('@').lower()`. **Точное равенство.** Для YT есть толерантный fallback (`find_yt_channel_name_matches`: prefix + len-diff 1, guard на неоднозначность), для **TT толерантности нет** → обрезанная строка не совпадает.

**Корреляция длины имени** (Ambassadori TT):
- Падают: `golden.square.dubai` (19, 6×), `yield.dubai.estates` (19, 7×), `dubai_asset_expert` (18, 6×).
- Проходят: `dubai.homes22` (13), `dubai_asset_exper` (17). `dubairealestate062` (18) проходит — обрезка по **ширине пикселей**, а не по числу символов (узкие цифры влезают, точки/широкие — нет).

Вывод: причина воспроизводима и логически замкнута. Аккаунты Ambassadori (длинные Dubai-имена) уникально провоцируют баг.

## Разбор premise-точек

- **«Масс-прогон 22.05».** Падения по датам: 15.05 — 38, 19.05 — 28, 22.05 — **7**. Запрос `events ILIKE '%retry_clean_slate%'` по Ambassadori → **0**. `publish_queue.last_retry_reason` ненулевой лишь у 3 слотов (25–27.05, `transient_within_limits`). Движок ретраев Ambassadori 22.05 массово не гонял; «22.05» = системная дата «чистого листа» (#108).
- **«На ручной с 25.05».** Все `done`-слоты (50 до 25.05 + 23 после) имеют `publish_task_id` и `manual_handoff_at IS NULL` → это авто, не ручная. `validator_projects.manual_publish = FALSE`, `manual_publish_set_at = 2026-05-27 07:42 UTC`. Похоже, проект на авто (и сегодня кто-то трогал флаг). **Нужна сверка с Аней/оператором, действительно ли проект должен быть на ручной.**

**Truncation-баг — Ambassadori-специфичен сегодня.** `tt_account_not_in_list` по всем проектам с длиной имени:
- Ambassadori — единственный с длинными именами (≥18): `yield.dubai.estates` (19), `golden.square.dubai` (19), `dubai_asset_expert` (18).
- У остальных — короткие имена (ClickPay `my_clickpay` 11, Art Estate `spb.home` 8, Relisme `packgirl24` 10) → **другая суб-причина** (аккаунт реально не на устройстве / разлогинен / непрозрачный дамп), не обрезка.
- `el_cosmo46` (10 симв., 28 падений, всё 27.05, аккаунт в `known`) — почерк сегодняшнего флитового спайка непрозрачных дампов **WP#131/#164**, не truncation. Сегодняшние TT-падения Ambassadori (`tt_profile_tab_broken`) — туда же.

**Итог риска truncation:** сегодня бьёт только Ambassadori (из-за конвенции длинных имён), но баг **латентен для любого будущего аккаунта с длинным/широким именем** на любом проекте.
