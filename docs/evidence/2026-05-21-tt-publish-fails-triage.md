## Разбор `tt_upload_confirmation_timeout` (7 задач)

Задачи: 8765, 8779, 8795, 8799, 8802, 8842, 8846.
У всех 7: `post_url` пустой, `url_capture_attempts=0` → задача падает ДО фазы захвата URL. Это **реальные не-публикации**, не false-negative URL-poller'а.

### Универсальная сигнатура (7/7)
Во **всех** случаях:
- AI-vision вернул `null` координаты для кнопки публикации (`ai_find_tap_no_coords`, desc='the Publish/Post/Опубликовать/Поделиться button…');
- XML не нашёл кнопку → тап по hardcoded fallback-координатам (`(816,2130)` и др.);
- подтверждение загрузки так и не пришло → watchdog 90s → таймаут 3 мин → fail.

Осложнения варьируются (commercial-music модалка — 4 задачи; music-rights чекбокс — 1; Samsung/in-app Story оверлей — 1), но **константа одна: кнопка публикации не локализуется надёжно, публикация фактически не происходит.**

### Под-режим A — кнопка Publish не находится (большинство, напр. 8765)
Скринкаст task 8765 (`…task8765_fail_screenrec…mp4`):
- в момент поиска кнопки экран перекрыт оверлеем «Добавить в историю» / TikTok in-app Stories («Ваша история» / «Далее»);
- к концу 9-мин ожидания телефон стоит на обычном экране публикации TikTok: красная кнопка **«Опубликовать» внизу справа** так и НЕ нажата, плюс **неотмеченный чекбокс** «Я принимаю Подтверждение прав на использование музыки».

**Дефекты кода (`publisher_tiktok.py`):**
1. **Устаревший AI-промпт (строки 1816–1817):** ищет кнопку *«usually blue or white button in top-right corner»*, тогда как реальная — **красная, внизу по центру/справа**. Это прямо противоречит комментарию самого кода (строка 1788: *«кнопка ВНИЗУ по центру (~554,1409), не вверху!»*) → AI-фолбэк обречён возвращать null.
2. **XML-поиск (строка 1790):** требует точного текста `'Опубликовать'/'Post'/'Publish'` И `clickable='true'`. Не матчит вариант текста «Опубликовать видео» и состояние, когда кнопка задизейблена (music-rights чекбокс не отмечен — в коде уже есть состояния `clickable='false'`, см. `tests/test_publisher_tt_music_rights.py`).
3. **Fallback-координаты `(816,2130)`** не попадают по кнопке надёжно (на Samsung 1080×2340 y≥2205 — gesture-nav strip; кнопка ~y2050).

### Под-режим B — необработанный модал «Подтвердите видимость публикации» (8799)
Скринкаст task 8799 (`…task8799_fail_screenrec…mp4`), события:
```
06:14:51 кнопка публикации найдена text='Опубликовать' pos=(798,2103) → нажата
06:15:07 music rights dialog accepted
06:15:16…06:24:16 post-music-rights dump saved (iter+1 … +40)  ← wait-loop 9 мин впустую
06:28:45 Публикация завершилась с ошибкой
```
Финальный кадр: чекбокс music-rights уже ✓, но поверх экрана висит блокирующий модал **«Подтвердите видимость публикации: Все»** с кнопкой **«Подтвердить»** — автоматизация её не нажимает.

**Дефект:** обработчика этого модала в `publisher_tiktok.py` НЕТ (`grep "идимост"` → 0; есть только music-rights «Подтвердить и опубликовать видео?»). Публикация блокируется этим диалогом → таймаут.

> Контекст: `tt_upload_confirmation_timeout` уже чинили (WP #82, PR #69, 2026-05-18 — early success-check / inferred_success). Сегодняшние 7 — остаточные/новые под-режимы: проблема локализации кнопки + новый необработанный visibility-confirm модал.

## Решение и исход

Выбран для фикса топ-1 — `tt_upload_confirmation_timeout` (50%). По screencast'ам/дампам разбит на два суб-режима:

- **Суб-режим B — модал «Подтвердите видимость публикации» → «Подтвердить»: ✅ SHIPPED+DEPLOYED 2026-05-21 (WP #118, PR #89, прод `7414891`).**
  Детектор + хендлер (`_detect/_handle_tt_visibility_confirm_dialog`, тап «Подтвердить» через `_strict_tap_clickable`), ветка в `wait_upload` loop после UPLOAD_OK, kill-switch `TT_VISIBILITY_CONFIRM_HANDLER_ENABLED`, cap=5 → `tt_visibility_confirm_stuck`. Плюс исправлен AI-промпт кнопки публикации (была «top-right blue/white» → стала «красная, внизу»; AI давал null в 39/41 таймаутов за 7д). 12 новых тестов, весь TT-набор (185) зелёный, codex clean.
- **Суб-режим A — оверлей «Добавить в историю» перекрывает экран во время share-loop (≈4/7 падений 20.05): 📋 BACKLOG (WP #122).**
  Существующие overlay-хендлеры работают только в фазе `wait_upload`, а не во время поиска/нажатия кнопки публикации. Не вошло в PR #89 из-за более высокого риска (основной путь публикации).

Метрика за 7д: 41 фейл `tt_upload_confirmation_timeout`, из них 20 (49%) дошли до post-publish состояния (кандидаты суб-режима B), 39/41 имели AI-null на кнопке. Верификация фикса — утренняя TT-пачка 22.05 (падение доли + события `tt_visibility_confirm_accepted`).
