# WP#189 — Механика загрузки контента для схем уникализации

**Дата:** 2026-05-29
**OpenProject:** #189 «Уникализация — механика для загрузки контента для схем уникализации»
**Репозитории:** `validator-contenthunter` (бэкенд FastAPI + фронт Vue). Воркер `unic-worker` — потребитель, **не меняется**.
**Ветка спеки/плана:** `wp189-unic-content-upload` (в `contenthunter`).

## Что нужно

В разделе «Уникализация → Контент» (`https://delivery.contenthunter.ru/#uniqualization/unic-content`, страница `frontend/src/pages/admin/UnicContentPage.vue`) добавить **отдельную** кнопку «Загрузить контент». Сейчас на странице есть только «Добавить контент» — ручной ввод метаданных (URL вставляется руками). Новая кнопка открывает модалку, которая **реально загружает файлы в S3** и создаёт строки в `validator_unic_content`, чтобы файлы корректно встроились в процесс уникализации.

## Ключевой контекст (эмпирически из прод-БД и кода)

Значения «тип контента» из ТЗ (`overlay_sounds`, …) — это **имена S3-папок**, а НЕ значения колонки `content_type`. Воркер уникализации (`unic-worker/worker.py`) фильтрует строки по своей таксономии (`audio`/`application`/`image`/`video` + `label LIKE 'logo%'`/`'pattern%'`). Чтобы файл «встроился», строка должна быть записана в правильной таксономии.

Факты из прода:
- S3: `https://s3.ru1.storage.beget.cloud/1cabe906ea6e-gengo/factory/<folder>/<file>`.
- `file_path` = **полный публичный URL** (воркер качает его через httpx, не по S3-ключу).
- Все видео в проде: `chromakey_color = '0x00ff30'`.
- Логотипы лежат **под проект** (`project_id = 54/50/…`, `label='logo'`); sounds/fonts/pattern/video — **универсальные** (`project_id = 0`).
- `system` (2 строки): служебные иконки `Status_Success_Icon.svg`/`Status_Error_Icon.svg`, `content_type='image'`, `label='system'` — воркер их не читает.
- Колонки `validator_unic_content`: `id, content_type, label, usage_type, project_id, duration, size, file_path, file_params(jsonb), chromakey_color`. Таблица уже в проде — **миграция не нужна**.

### Расхождение usage_type ↔ воркер (решение принято)

Воркер потребляет sounds/fonts/pattern/video **только как универсальные** (`project_id=0`), а logo — **только под проект**. Решение Данила: **полная свобода без проверок** — форма разрешает любой тип с любым usage, ответственность на операторе, предупреждений не показываем.

## Решения по уточнениям

1. **`system`** — служебные файлы (UI-иконки). Оставляем в дропдауне; грузим в `factory/system/`, `content_type='image'`, `label='system'`; в уникализацию не идёт.
2. **chromakey** — опциональное поле, появляется только при `overlay_video`, дефолт `0x00ff30`, оператор может изменить.
3. **usage_type** — свобода без проверок (см. выше).

## Архитектура

Выбран **Вариант A — серверная загрузка**. Фронт шлёт `multipart/form-data` (файлы + метаданные) на новый эндпоинт; бэкенд валидирует, грузит каждый файл в S3 через существующий `_upload_bytes_to_s3` (мультипарт), вставляет строку. Один запрос, переиспользуется паттерн `brand.py`, сервер атомарно владеет генерацией ключа/папки/label.

(Отклонён Вариант B — presigned direct-to-S3: двухфазно и избыточно для мелких оверлеев.)

### Маппинг «тип контента» (серверная константа)

| Дропдаун (`content_kind`) | S3 `factory/…` | `content_type` | `label` префикс | допустимые расширения |
|---|---|---|---|---|
| `overlay_sounds` | `overlay_sounds/` | `audio` | `sounds` | `.mp3` |
| `overlay_fonts` | `overlay_fonts/` | `application` | `fonts` | `.ttf`, `.otf` |
| `overlay_pattern` | `overlay_pattern/` | `image` | `pattern` | `.png` (SVG запрещён) |
| `overlay_logo` | `overlay_logo/` | `image` | `logo` | `.png` (SVG запрещён) |
| `overlay_video` | `overlay_video/` | `video` | `video` | `.mp4` (+ chromakey) |
| `system` | `system/` | `image` | `system` | любой |

SVG для `overlay_logo`/`overlay_pattern` **запрещён**: прод-воркер `unic-worker` его не растеризует → FFmpeg «Invalid PNG» (зеркало гарда в `brand.py`, инцидент «SVG роняет уникализацию»).

### Backend

Новый эндпоинт `POST /api/unic-content/upload` (admin-only, как существующие create/update/delete).

**Вход** (`multipart/form-data`):
- `files[]` — один или несколько файлов;
- `content_kind` — одно из значений маппинга;
- `usage_type` — `Универсально (любой проект)` | `Под проект (один конкретный проект)`;
- `project_id` — int, опционально (используется при «Под проект»);
- `chromakey_color` — str, опционально (только для `overlay_video`).

**Логика на каждый файл:**
1. Проверка расширения по маппингу (иначе понятная ошибка по конкретному файлу).
2. S3-ключ `factory/<folder>/<uuid>.<ext>`; загрузка через `_upload_bytes_to_s3`; публичный URL через `get_public_url()`.
3. `project_id` = выбранный проект при «Под проект», иначе `0`.
4. `label` = `<prefix>_<project_id>_<seq>`, где `seq` = следующий по существующим строкам того же `(prefix, project_id)`. Для `system` → `label='system'`.
5. `chromakey_color` пишется только для video (дефолт `0x00ff30`), иначе `null`.
6. `size` = размер в Мб (`bytes/1024/1024`), `duration` = `null`, `file_params` = `null`.
7. INSERT строки.

**Ответ:** список созданных строк (поля как у `GET /api/unic-content`) + список ошибок по файлам, если были. Частичный успех допустим: хорошие файлы загружаются, по плохим — ошибка.

Без проверок соответствия usage_type ↔ тип (свобода).

### Frontend (`UnicContentPage.vue`)

Вторая кнопка «⬆ Загрузить контент» рядом с «Добавить контент». Новая модалка (паттерн существующих `Teleport`-модалок, стили `.input-field`/`.field-label`):
- мультизагрузка файлов (`<input type="file" multiple>`);
- селект «тип контента» — 6 человекочитаемых опций (значение = `content_kind`);
- селект «тип использования» — 2 опции;
- селект «Проект» — появляется при «Под проект», populate из `GET /api/projects`;
- поле chromakey — появляется при `overlay_video` (дефолт `0x00ff30`);
- кнопка «Загрузить» → `multipart` POST → при успехе перезагрузить таблицу (`GET /unic-content`), закрыть модалку; показать ошибки по файлам.

## Тестирование (TDD)

Бэкенд (зеркало существующих тестов роутеров):
- валидация расширений по каждому `content_kind` (включая запрет SVG для logo/pattern);
- корректность маппинга `content_kind` → (`content_type`, `folder`, `label` префикс);
- генерация `label` и `seq` (последовательность по `(prefix, project_id)`);
- `project_id`-логика (универсально → 0; под проект → выбранный);
- `chromakey_color` только для video;
- вставка строк (S3-загрузка замокана);
- частичный успех (часть файлов невалидна).

Фронт — по нормам репозитория (минимально/без, если в репо так принято).

## Границы (out of scope)

- Изменения схемы `validator_unic_content` (таблица уже есть).
- Правки воркера `unic-worker` (включая доработку под per-project sounds/fonts/pattern/video и SVG-растеризацию).
- Редактирование/удаление существующих строк (уже реализовано на странице).
- Probe длительности (`duration`) — оставляем `null`, при необходимости бэкфилл отдельно.

## Риски / проверить при реализации

- **Регистрация роутера**: подтвердить, что `unic_content.router` подключён в `backend/src/main.py` (страница `GET /unic-content` живёт в проде → вероятно подключён; разведка по одному чекауту утверждала обратное — проверить на актуальном).
- **S3-конфиг валидатора vs воркер**: `file_path` должен быть публичным URL, достижимым воркером (`save.gengo.io`/`s3.ru1.storage.beget.cloud/1cabe906ea6e-gengo`). Подтвердить, что прод-`.env` валидатора пишет URL в том же бакете/CDN, что качает воркер.
- **Лимит размера**: задать разумный max на файл (видео); мультипарт-загрузка крупные тянет, но нужен предохранитель.
