**Дата:** 2026-05-29
**OpenProject:** #161 (исполнитель Данил) → «В разработке»
**Предыдущая итерация:** `docs/superpowers/specs/2026-05-27-wp161-tg-approval-notify-design.md` (SHIPPED+DEPLOYED 27.05)
**Модуль:** `approval_notify.js` (autowarm) + `telegram_send.js` + миграция `approval_notify_runs`

## Контекст

WP#161 iter1 отгружен и работает в проде: почасовая (09–18 МСК) Telegram-сводка в тред «Модерация и уникал» — ролики `needs_review` + клиенты без контента на завтра/послезавтра. После недели эксплуатации автор (Анастасия/Аня) открыла задачу заново с серией доработок и нашла баг (комментарии OP 28–29.05).

## Проблемы

1. **Баг блока «контент не загружен» (ложные срабатывания).** Текущий SQL флагует клиента, если на завтра/послезавтра пуст **хотя бы один** слот. У большинства проектов на день заведено 2 слота, один из которых обычно пуст → в список попадают почти все активные проекты, хотя контент на день у них есть. Подтверждено на живых данных 29.05: ClickPay/Splus/PANDAFiT имеют заполненный слот на оба дня, но числятся «без контента»; реально без контента только AXILOR Private на 31.05.

2. **Блок «на одобрении» показывает нерелевантные старые ролики.** Накопились `needs_review` с плановыми датами в прошлом — они засоряют сводку.

3. **Блоки «завтра» и «послезавтра» слиты в один список.** Аня просит разделить — отдельными абзацами понятнее.

4. **Слишком частая рассылка.** Почасовое окно 09–18 избыточно — нужен один утренний отчёт.

## Решения (согласованы с Данилом 29.05)

| Развилка | Решение |
|---|---|
| Правило «нет контента» | День пуст = **0 заполненных слотов** в этот день у проекта (а не «есть пустой слот») |
| Фильтр блока «на одобрении» | Плановая дата **≥ сегодня** (МСК); ролики только с прошлыми датами — убрать |
| Ролики `needs_review` без даты | **Скрывать** (строгий фильтр по дате; в рассылку не попадают) |
| Раздельность дней | «Нет контента на завтра» и «на послезавтра» — **отдельными абзацами** |
| Каденция | **1 раз в день, 09:00 МСК** (вместо почасового окна) |
| Проект без слот-строк на день | В «нет контента» **не попадает** — учитываем только дни с заведёнными слотами |

## Дизайн

### Блок 1 — «На одобрении» (SQL #1 в `buildApprovalSummary`)

Добавить фильтр по плановой дате:

- Ролик `needs_review` попадает в сводку, только если у него есть **хотя бы один** слот с `slot_date >= :today`.
- В выводимые даты (`array_agg`) включаются только даты `>= :today`.
- Ролики без слотов и ролики только с прошлыми датами — исключаются (через `HAVING count(...) > 0` по будущим датам).
- Счётчик «N роликов на одобрении» = число роликов, прошедших фильтр.

`:today` — текущая дата в МСК (UTC+3), как `::date`.

### Блок 2 — «Нет контента» (SQL #2 — переписать)

Заменить «есть пустой слот» на «день полностью пуст», с разбивкой по дням:

- Для каждого активного проекта (`vp.active = true`) и каждого из дней `{tomorrow, dayAfter}`:
  день считается пустым, если среди слотов проекта на этот день **нет ни одного заполненного** (`content_id IS NOT NULL`).
- Реализация: `GROUP BY project, slot_date HAVING count(*) FILTER (WHERE content_id IS NOT NULL) = 0`.
- Возврат: список пар `(client, day)` (а не `DISTINCT client`). Дни разделяются на стороне форматтера.
- Проекты без слот-строк на день в выборку не попадают (нет строки — нет группы); это соответствует согласованному решению.

### Форматирование (`formatMessage`)

Блок «нет контента» — раздельные абзацы по дням, каждый показывается только при наличии клиентов:

```
📭 <b>Нет контента на завтра (30.05):</b>
client1, client2

📭 <b>Нет контента на послезавтра (31.05):</b>
AXILOR Private
```

Блок «на одобрении» — без изменений в верстке, но даты уже отфильтрованы (`>= today`); вариант «дата не назначена» исчезает (бездатные скрыты на уровне SQL).

Если оба блока пусты — прежнее `✅ Всё одобрено...` (с `APPROVAL_NOTIFY_SUPPRESS_EMPTY`). Упоминание `@gengo_care` в конце сохраняется.

### Каденция (`_tickOnce`, `startApprovalNotifyCron`)

- Почасовое окно → **однократная отправка в `09:00 МСК`** по образцу `daily_publish_report.js` (60с тик, совпадение времени, catch-up в течение дня).
- Идемпотентность: ключ claim меняется с «часового бакета» на **«дневной бакет»** (начало МСК-суток в UTC). Таблица `approval_notify_runs` переиспользуется — тип PK (`timestamptz`) совпадает, миграция не требуется.
- ENV: `APPROVAL_NOTIFY_WINDOW` (формат `start-end`) **заменяется** на `APPROVAL_NOTIFY_TIME_MSK` (формат `HH:MM`, default `09:00`). Логировать выбранное время при старте крона.
- Сохраняются: `APPROVAL_NOTIFY_ENABLED` (kill-switch), `APPROVAL_NOTIFY_SUPPRESS_EMPTY`, `APPROVAL_NOTIFY_MAX_ATTEMPTS`, `APPROVAL_NOTIFY_MENTIONS`, токен/чат/тред.

## Тестирование

Юнит-тесты (TDD, расширить существующий набор):

- `formatMessage`: раздельные абзацы «завтра»/«послезавтра»; абзац дня скрыт при пустом списке; счётчик роликов; оба блока пусты.
- Правило «нет контента»: день полностью пуст → попадает; день частично заполнен (1 из 2) → НЕ попадает; оба дня пусты → попадает в оба абзаца.
- Фильтр блока «на одобрении»: ролик с будущей датой → виден; только прошлые даты → скрыт; без даты → скрыт; смешанные даты → только будущие в выводе.
- Каденция: совпадение по `09:00 МСК` → отправка; вне времени → нет; дневной claim идемпотентен (повтор в тот же день → skip).

SQL-логика проверяется смоком на живой БД `openclaw` (как в iter1): `node approval_notify.js --dry-run` сверить, что AXILOR на 31.05 присутствует, а ClickPay/Splus/PANDAFiT — нет.

## Деплой

1. Push в **GenGo2/delivery-contenthunter `main`** → прод (`/root/.openclaw/workspace-genri/autowarm`, ветка main) `git pull`.
2. `sudo pm2 restart autowarm` — крон перечитает `APPROVAL_NOTIFY_TIME_MSK`.
3. Прод `.env` под root: `APPROVAL_NOTIFY_WINDOW` можно убрать (игнорируется); явный `APPROVAL_NOTIFY_TIME_MSK` не обязателен (default 09:00).
4. Смок `node approval_notify.js --dry-run` в проде → сверить оба блока на живых данных.
5. Миграция не требуется (`approval_notify_runs` переиспользуется).

Kill-switch `APPROVAL_NOTIFY_ENABLED=0` наготове. Риск низкий — точечная правка живого модуля, поведение за флагом.
