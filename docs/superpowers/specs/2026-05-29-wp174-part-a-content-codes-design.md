# WP#174 Часть A — Коды роликов (RLM-014)

**Дата:** 2026-05-29
**Задача:** OpenProject #174 «Таблица Лог событий» (ЧАСТЬ A из двух).
**Статус:** дизайн утверждён, готов к плану.

## Контекст и цель

Клиенты дают роликам одинаковые заголовки («Привет!», «Новинка»), команда не может однозначно сослаться на конкретный ролик в чате. Вводим короткий читаемый идентификатор контента формата `PREFIX-NNN` (например `RLM-014`), авто-генерируемый при загрузке. Это фундамент для Части B (Lifecycle View), где код — первая колонка.

Часть A независимо отгружаема и тестируема, реализуется первой.

## Репозитории

- **`validator-contenthunter`** (FastAPI / alembic) — модель, генерация, авто-присвоение, бэкфилл, видимость в клиентском планировщике.
- **`delivery-contenthunter`** (`server.js`, vanilla `public/index.html`) — **только чтение** кода для отображения в админских таблицах.

## Решения (из брейншторма)

- Префикс: **авто-детерминированный + ручной override** админом.
- Хранение: **номер на контенте + префикс на проекте, полный код рендерится на лету** (смена префикса авто-переименовывает все коды проекта, нет дрейфа денормализации).
- Sequence: **счётчик-колонка на проекте + `UPDATE ... RETURNING`** (race-safe, без дыр).

## A1. Модель данных (миграция, alembic в validator-contenthunter)

`validator_projects` (+2 колонки):
- `code_prefix` TEXT — 3-буквенный префикс, **UNIQUE constraint**.
- `code_seq` INT NOT NULL DEFAULT 0 — счётчик выданных номеров проекта.

`validator_content` (+1 колонка):
- `code_number` INT NULL — порядковый номер ролика в рамках проекта.

**Полный код** = `code_prefix + '-' + pad(code_number)`, считается на лету в сериализации API/UI:
- Padding до 3 цифр: `001`, `014`, `999`.
- После 999 — без префиксных нулей: `1000`, `1234`.

Смена префикса проекта автоматически переименовывает все коды проекта (т.к. строка кода не хранится).

## A2. Генерация префикса (общий сервис `prefix_service.py`)

База: первые 3 латинские буквы из `_transliterate(project_name)` (уже существует в `clients.py`), uppercase.
- `Relisme → REL`, `Эзотерика → EZO`, `Art Estate → ART`.
- Если латинских букв < 3 — добивка символом `X`.

**Разрешение коллизий** (детерминированно, по порядку, до первого свободного префикса):
1. `base3`
2. `base2 + цифра 2..9` (`RE2`…`RE9`)
3. `base1 + следующие латинские буквы названия`

Если всё занято — ошибка с предложением задать вручную.

**Ручной override**: админ задаёт/меняет префикс в карточке проекта через `PUT /api/projects/{id}`.
- Валидация: 2–4 символа `[A-Z0-9]`, UNIQUE (иначе 409).

Сервис вызывается из **обоих** путей создания проекта:
- `clients.py::register_client`
- `projects.py::create_project`

## A3. Авто-присвоение кода ролика

При создании контента — атомарная выдача номера:
```sql
UPDATE validator_projects SET code_seq = code_seq + 1 WHERE id = :pid RETURNING code_seq
```
Результат пишется в `validator_content.code_number`.

Хелпер `assign_content_code(db, project_id) -> int` вызывается во **всех 4 точках вставки** `validator_content` в `upload.py` (видео / карусель / пост / bulk).

**Safety-net**: миграционный/фоновый проход проставляет `code_number` любому контенту, где он `NULL` (на случай пропущенного пути вставки).

## A4. Бэкфилл легаси (одна миграция)

Для каждого проекта:
1. Сгенерировать `code_prefix` из имени проекта (с разрешением коллизий по A2).
2. Проставить `code_number` всему существующему контенту последовательно по `created_at ASC` в рамках проекта.
3. Выставить `code_seq = MAX(code_number)` проекта (новые коды идут после легаси).

Cutoff на легаси НЕ делаем (B.9): контент до 22.05.2026 показывается с присвоенным кодом, без спец-фильтрации.

## A5. Видимость (role check)

- **Админские таблицы** (Запланировано / Опубликовано / Lifecycle View / карточка контента) — код всегда первой колонкой.
- **Клиентский планировщик** — код виден **только админам** (`role == admin`); клиенту код не отдаётся в сериализации.
- **Delivery (`server.js`)** — только читает код (JOIN `validator_projects` для префикса) и показывает в своих таблицах.

## A6. Тестирование

- **Unit (prefix_service):** генерация из транслита; коллизии (`REL` занят → `RE2`…); pad (`014`, `1000`); translit edge-cases (название без латиницы → `X`-добивка).
- **Concurrency:** параллельные `assign_content_code` для одного проекта не дают дублей `code_number` (проверка `UPDATE ... RETURNING`).
- **Backfill:** легаси получает последовательные коды per project по `created_at`; `code_seq` сдвинут на `MAX`.
- **Override:** `PUT /api/projects/{id}` меняет префикс, коды переименовываются; коллизия → 409; невалидный формат → 400.
- **Role:** клиенту код не отдаётся, админу — да (оба пути сериализации).

## Объём

1 alembic-миграция (схема + бэкфилл) + `prefix_service.py` + правки 2 эндпоинтов создания проекта + 4 хука в `upload.py` + проброс кода в сериализацию (валидатор API + delivery `server.js`) + фронт-колонка «Код».
