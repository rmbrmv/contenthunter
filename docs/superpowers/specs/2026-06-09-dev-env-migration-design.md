# Перенос dev-хаба Claude на новый сервер — дизайн

**Дата:** 2026-06-09
**Статус:** Фаза 0 выполнена; Фазы 1–2 — к реализации
**Связано:** `project_ch_server_migration` (катовер прода 08.06)

## Проблема

Бокс **fra-1-vm-y49r = 72.56.107.157** (он же СТАРЫЙ прод) скоро гасится. На нём
живёт не только разработка, а весь **операционный хаб Claude**: база знаний,
Telegram-агенты, конвейер ингеста, плюс несколько ещё работающих прод-сервисов.
Нужна схема, при которой:

1. База знаний продолжает накапливаться и переживает гашение бокса.
2. Claude Code сохраняет полный root-контроль над сервером и кодовой базой.
3. Код и база знаний синкаются через GitHub — доступ у PM и руководителя.
4. Возможна работа с локального ПК.

## Согласованная схема работы

| Слой | Где | Доступ |
|---|---|---|
| Код | `rmbrmv/contenthunter` | PM + рук (есть) |
| База знаний Claude (`memory/`) | `GenGo2/contenthunter_memory` (приватный) | + PM/рук коллабораторами |
| Knowledge/багрепорты | `GenGo2/contenthunter_knowledge` (есть) | на gengo2 |
| Dev-«дом» Claude Code | ко-локация на новом проде **46.225.145.245** (root) | — |
| Локальный ПК | тонкий клиент → **Termius SSH** в новый сервер | — |

**Принципы:**
- Единый always-on «дом» на новом проде = единственный источник правды для
  памяти. Локальный ПК своей копии памяти НЕ держит (Termius SSH only) → ноль
  мердж-конфликтов `MEMORY.md`.
- Телефоны тестбенча по сети (ADB over IP), к боксу не привязаны → среда
  переносима без привязки к железу.
- Память и код авто-синкаются на GitHub → у PM/рук всегда актуальный доступ.

## Фаза 0 — спасение памяти ✅ ВЫПОЛНЕНО+ВЕРИФ

- Создан приватный репо `GenGo2/contenthunter_memory` (user account; через
  GitHub API `user/repos`, токен из `~/.config/contenthunter_knowledge/github.env`).
- `memory/` → git-репо; remote token-less; креды через
  `credential.helper store --file=~/.config/contenthunter_knowledge/git-credentials`
  (тот же GenGo2-токен, без токена в `.git/config`).
- Первый пуш: 246 файлов + `.gitignore` = 247 на remote, верифицировано через API.
- Временный авто-синк на старом боксе: `~/.local/bin/sync-claude-memory.sh` +
  cron `*/15` (commit+push при изменениях).
- Скан секретов чистый, кроме `project_autowarm_code.md`: пароль localhost-БД
  `openclaw123` (низкий риск, приватный репо).

## Фаза 1 — перенос хаба на 46.225.145.245

Цель: воспроизвести операционный хаб на новом проде, переключить туда авто-синк,
оставив старый бокс «холодным» дублёром на время Фазы 2.

1. **Dev-среда:** клон `rmbrmv/contenthunter` на новый сервер под нужным
   пользователем; перенести `~/.claude` (конфиг+plugins), `~/.codex`,
   `~/.ssh` (ключи доступа к телефонам/прод/БД), `~/.config`/`~/.secrets`.
2. **Память:** склонировать `GenGo2/contenthunter_memory` в путь памяти Claude
   на новом сервере; настроить **постоянный** авто-синк (cron `*/15` или
   `Stop`-hook). Старый cron на 72.56.107.157 отключить после переключения.
3. **Knowledge + ингест:** перенести `~/contenthunter_knowledge` (pull из gengo2),
   `/opt/ingest/` (скрипты+cron), `~/contenthunter_bugs_bot/` (с `bot.env`).
   Перевести Telegram-ингест на новый сервер; убедиться, что коммиты бота идут в
   `GenGo2/contenthunter_knowledge` без дублирования со старым боксом
   (на старом — остановить ингест/бот до запуска на новом).
4. **Агенты:** воссоздать `tg` и `kira` Telegram-Claude агенты (tmux+system-prompt)
   на новом сервере; на старом — остановить, чтобы не было двойной обработки.
5. **Гигиена git:** в `rmbrmv/contenthunter` remote URL содержит вшитый токен
   `rmbrmv` (`ghp_…`) — заменить на credential helper, токен убрать из `.git/config`.

**Критерий готовности Ф1:** на новом сервере работает интерактивный Claude Code
с root; память+knowledge авто-синкаются туда; агенты/ингест работают только на
новом сервере; старый бокс ничего активно не пишет.
