# WP #163 — Ambassadori: автопубликация падала до перевода на ручную (триаж)

**Тип:** discovery / триаж (классификация B). Не scoped-фикс — диагностика неизвестной первопричины с анализом продовой БД. Результат — находки + решения, фиксы выносятся отдельными дочерними WP.

**Дата:** 2026-05-27. **Ветка:** `worktree-wp163-ambassadori-autopublish-triage`.

## Задача

До перевода Ambassadori на ручную выкладку (премиса: 25.05) автопубликация часто не проходила — серии неуспехов и массовый повторный прогон 22.05. Нужно: (1) понять первопричину падений авто-тракта Ambassadori; (2) проверить, не повторяется ли то же на других проектах. Отдельный сюжет от #155 (там чинили только переполнение ручной очереди старыми задачами).

## Согласованный объём (с Данилом, 2026-05-27)

1. **Результат:** полноценный evidence-док (`docs/evidence/`) с первопричинами + списком предлагаемых дочерних WP **внутри доки**; сами WP не заводить без отмашки (правило дома). Плюс комментарий в OpenProject #163 по house-style.
2. **Охват кросс-проверки:** все активные проекты с заметным fail-rate авто-тракта в окне до 25.05.
3. **Авто-тракт Ambassadori:** цель — понять историческую причину + убедиться, что не рецидивит. Код авто-тракта Ambassadori в рамках #163 **не правим** (фиксы — отдельными WP).
4. **Подход:** B — агрегат по `meta.category` + точечный deep-dive (screencast/dump) по доминирующим/неоднозначным бакетам.

## Источники данных и связка

- `validator_projects` (id, project, active, manual_publish, manual_publish_set_at) — реестр проектов, кто активен. Ambassadori = **id 58**.
- `publish_queue` (project_id, platform, status, scheduled_at, publish_task_id) — исходы на уровне слотов.
- `publish_tasks` (events JSONB, status, platform, created_at, error_code, error_class, screen_record_url) — детали попыток. Связка: `publish_queue.publish_task_id → publish_tasks.id`. На один слот возможно несколько попыток (ретраи).
- **Сигнал первопричины** = последний элемент `events` с `type='error'` → `meta.category`. `error_code`/`error_class` **игнорируем** (фиксируют первую/preflight-ошибку — врут). Подтверждено на task 11071: последняя error-категория = `tt_profile_tab_broken`.

## Временное окно

«Авто-эра» Ambassadori: слоты 14.05–29.05. Окно «почему падало до ручной» = `scheduled_at < 2026-05-25`. В доке — оба среза: по слотам (queue) и по попыткам (tasks).

## Методология (на проект × платформу)

1. Достать `failed` в окне → извлечь **последнюю** error-категорию → бакеты по платформам.
2. Исключить транзиенты: `adb_devices_unreachable`, `process_interrupted` (PM2-шум при деплое), `watchdog_subprocess_hang` (#165, инфра-инцидент 27.05 — не код проекта).
3. **Развести «масс-прогон 22.05»:** проверить, это «чистый лист» движка ретраев (#108, запуск 05:00 МСК 22.05), пере-прогонявший уже упавшие слоты, или новые падения — по cpid / retry-маркерам (`retry_clean_slate_20260522`, `last_retry_reason`).
4. Сопоставить доминирующие бакеты с известными первопричинами: `tt_profile_tab_broken` (#131/#164), `yt_create_menu_not_reached`, SVG→Invalid PNG (#149/#150), IG fg-guard over-fire (#119, откат), `account_blocks` (заморозки).
5. **Deep-dive (подход B):** по каждому доминирующему/неоднозначному бакету — 1–2 репрезентативных падения: screencast (`screen_record_url`) + ffmpeg-кадры или UI-dump, чтобы подтвердить настоящую первопричину, а не generic-метку. **Caveat:** для падений 14–24.05 screencast'ы в S3 могли ротироваться — где артефакта нет, остаёмся на агрегатной метке (помечаем явно).

## Кросс-проверка всех активных проектов

Для каждого `active=true` проекта — fail-rate по платформам в окне до 25.05 + топ error-категории. Помечаем проекты, делящие доминирующие первопричины Ambassadori. Вывод — сравнительная таблица + список затронутых проектов.

## Реальность флага (находка для проверки)

В БД у Ambassadori сейчас `manual_publish=false` (= авто), `manual_publish_set_at = 2026-05-27 07:42 UTC` (сегодня) — расходится с премисой «на ручной с 25.05». Похоже, проект вернули на авто. Фиксируем как находку; цель не меняется (понять причину + не рецидив).
