- **Дата:** 2026-05-26
- **Автор:** Claude (по запросу Данила)
- **Связанные WP:** #95 (закрыть superseded), #149 (Anecole контент), #151 (хардненг уникализации)
- **Репозитории:** `validator-contenthunter` (backend, гард ②), `delivery-contenthunter/unic-worker` (воркер, сеть ③ + скрипт ①)
- **БД:** локальный Postgres `openclaw` (креды — из `unic-worker/ecosystem.config.js` env / секретов, не в этом доке)

## 1. Контекст и корневая причина

Воркер уникализации (`unic-worker/worker.py`) собирает ролики через FFmpeg, накладывая логотип проекта поверх видео. Логотип берётся из `validator_brand_profiles.logo_url` (приоритет 1), либо из `validator_unic_content` (`label LIKE 'logo%'`, legacy). Файл скачивается во временный `*_logo.png` и подаётся в FFmpeg как `-i` вход.

**Если `logo_url` указывает на SVG, FFmpeg падает:** `Invalid PNG signature 0x3C73766720776964` (hex = ASCII `<svg wid`). Это роняет **все схемы** задачи (логотип — общий вход), задача уходит в `current_status='error'`, контент не создаётся → очередь публикации не наполняется → клиент встаёт.

**Систематический скан `validator_brand_profiles.logo_url` (26.05) нашёл 2 активных проекта с SVG-логотипом:**

| Проект | onboarding_stage | logo_url | Состояние |
|---|---|---|---|
| Pimble (79) | 5 (боевой) | S3 `brand/79/logo/…svg` | реально встал, нет контента с 14.05 |
| Project 113 | 2 (онбординг) | внешний `https://bestclinic.ru/img/logo.svg` | латентный — встанет на этапе публикации |

Anecole (84) уже чист — его `logo_url` сейчас PNG; нужен только перезапуск застрявших задач. Паттерны (`label LIKE 'pattern%'`, `project_id=0`) — все PNG из общей фабрики, проблемы нет.

Загвоздка: у Pimble нет другого логотипа (в `validator_unic_content` 0 картинок), поэтому «заменить на другой PNG проекта» невозможно — единственный корректный путь — **растеризовать сам SVG в PNG**, сохранив настоящий логотип.

## 2. Цели и не-цели

**Цели:**
1. Починить уже сломанные проекты (Pimble 79, project 113) — растеризовать их SVG-логотипы в PNG, перезалить в S3, обновить `logo_url`, перезапустить застрявшие задачи.
2. Не дать SVG-логотипу попасть в систему через загрузку (гард в validator backend).
3. Сделать воркер устойчивым: даже если SVG просочился (внешний URL, легаси), не ронять пайплайн — растеризовать на лету (= хардненг #151).

**Не-цели:**
- Не меняем брендинг клиента (растеризуем именно его SVG, не подставляем чужие картинки).
- Не трогаем общие паттерны/видео/аудио фабрики (они PNG/корректны).
- Не переписываем мастер схем и не меняем формат `unic_schemes`.
- Не вводим конвертацию других векторных форматов (только SVG; YAGNI).

## 3. Архитектура: три компонента

### ① Разовая ремедиация (скрипт `unic-worker/scripts/fix_svg_logos.py`)

Назначение: одноразово (идемпотентно) найти и починить уже существующие SVG-логотипы.

**Детекция (двойная, чтобы поймать и `.svg`, и SVG под видом `.png`):**
1. По расширению/URL: `logo_url ILIKE '%.svg'`.
2. По содержимому: скачать первые ~512 байт, проверить сигнатуру — лидирующие пробелы/BOM, затем `<svg` или `<?xml` (с последующим `<svg`). Это ловит замаскированные SVG.

Скан охватывает `validator_brand_profiles.logo_url` (основной источник) и, защитно, `validator_unic_content` с `content_type='image' AND label LIKE 'logo%'`.

**Починка каждого найденного:**
1. Скачать SVG (httpx, follow_redirects — внешние URL вроде bestclinic.ru тоже).
2. Растеризовать через `cairosvg.svg2png` → PNG (см. §4 параметры).
3. Залить новый объект: ключ `brand/{pid}/logo/{uuid}.png` (для внешних URL — тот же шаблон ключа, переносим в наш S3), `ContentType=image/png`.
4. `UPDATE validator_brand_profiles SET logo_url=<новый PNG url> WHERE project_id=$1` (и/или соответствующую строку `validator_unic_content`).
5. Залогировать `pid, old_url, new_url`.

**Перезапуск контента:** после починки логотипа проекта — сбросить его застрявшие задачи:
`UPDATE unic_tasks SET current_status='pending', error_message=NULL, schemes_done=0, schemes_error=0 WHERE project_id=$1 AND current_status='error' AND task_type='unic'`.
Воркер заберёт их (`get_pending_task` поллит `current_status='pending'`).

**Безопасность:** флаг `--dry-run` (по умолчанию печатает план без изменений), `--project-id N` для точечного прогона, идемпотентность (повторный запуск на уже-PNG ничего не делает — детекция не срабатывает).

### ② Гард при загрузке (validator `backend/src/routers/brand.py`, эндпоинт `/upload-image`)

Сейчас эндпоинт явно разрешает `image/svg+xml` в `ALLOWED_IMAGE_MIMES` и кладёт SVG как есть. Меняем поведение:

- После `data = await file.read()`: определить, SVG ли это (mime `image/svg+xml` **или** content-sniff `<svg`/`<?xml`).
- Если SVG → растеризовать в PNG (§4), переопределить `ext='png'`, `mime='image/png'`, дальше обычный путь (`key=brand/{pid}/{field}/{uuid}.png`, `_upload_bytes_to_s3`, `get_public_url`).
- Клиент по-прежнему может загружать SVG (UX не ломаем), но в S3/БД логотип-SVG больше не попадёт.
- Лог: `[svg-guard] pid=… field=… rasterized svg→png bytes_in=… bytes_out=…`.

Применяем как минимум к `field='logo'`; распространить на остальные image-поля, т.к. FFmpeg ингестит и логотип, и потенциально другие картинки.

### ③ Сеть на стороне воркера (`unic-worker/worker.py`) — хардненг #151

Точка вставки — сразу после `download_file(...)` логотипа/паттерна (≈стр. 408–414), до построения FFmpeg-команды.

- После скачивания во временный файл: прочитать первые байты; если это SVG (`<svg`/`<?xml`) → растеризовать на месте в PNG (перезаписать тот же путь корректным PNG), залогировать.
- Это покрывает: внешние URL (project 113), легаси-данные, всё что обошло гард ②.
- Дополнительно: даже после конвертации сохранить существующую per-scheme обработку ошибок — один битый ассет не должен ронять всю задачу (текущая логика уже трекает per-scheme `scheme_errors`; конвертация общего логотипа разово снимает системный кейс).
- Добавить `cairosvg` в `unic-worker/requirements.txt`.

## 4. Параметры растеризации (общие для ①②③)

Единый хелпер, чтобы поведение совпадало во всех трёх местах. В воркере — модуль `unic-worker/svg_raster.py`; в validator — `backend/src/services/svg_raster.py` (зеркальная функция, ~10 строк).

```python
import cairosvg
def rasterize_svg_to_png(svg_bytes: bytes, *, width: int = 1024) -> bytes:
    # output_width задаёт растр; высота — пропорционально. Прозрачный фон по умолчанию (RGBA).
    return cairosvg.svg2png(bytestring=svg_bytes, output_width=width)
```

- **Прозрачность:** cairosvg по умолчанию даёт RGBA с прозрачным фоном — это критично для наложения логотипа.
- **Размер:** ширина 1024px — запас по качеству (схемы масштабируют логотип `logo_scale≈100–114`); высота пропорционально. Без апскейла растровых исходников (они уже PNG, в конвертацию не попадают).
- **Детект SVG (общий):** `_looks_like_svg(head: bytes) -> bool` — strip ведущих пробелов/BOM, проверка на `b'<svg'` или `b'<?xml'` (для xml — есть ли далее `<svg`). Используется и в sniff-ветке гарда, и в скрипте, и в воркере.

## 5. Обработка ошибок

- **Битый/непарсимый SVG:** `cairosvg` бросает исключение. 
  - Скрипт ①: логировать, пропустить проект (не падать целиком), вывести в итоговый отчёт «не удалось — нужен ручной перезалив».
  - Гард ②: вернуть `HTTPException(400, "Не удалось обработать SVG; загрузите PNG/JPEG")` — не глотать молча.
  - Воркер ③: если конвертация не удалась — оставить текущее per-scheme поведение (схема падает с понятным сообщением), не ронять весь процесс; залогировать.
- **S3 upload fail:** существующий `_upload_bytes_to_s3` уже с ретраями; скрипт наследует.
- **Внешний URL недоступен (113):** httpx timeout/4xx → логировать, пометить в отчёте, не падать.

## 6. Kill-switches и деплой

Все новые ветки — за env-флагами (дефолт ON, можно мгновенно выключить):
- Гард ②: `BRAND_SVG_RASTERIZE_ENABLED` (validator). Off → старое поведение (принимать SVG как есть).
- Сеть ③: `UNIC_SVG_RASTERIZE_ENABLED` (воркер). Off → старое поведение.

**Деплой:**
- Воркер (③ + скрипт ①): репо `GenGo2/delivery-contenthunter`, прод `/root/.openclaw/workspace-genri/autowarm/unic-worker`, авто-пуш post-commit хук. После мёрджа — `pip install cairosvg` в python3-окружении воркера (проверить, что подтянулся), `sudo pm2 restart unic-worker`.
- Validator (②): прод-бэкенд под PM2 `validator` (id=24); деплой кода + `sudo pm2 restart validator`. (Фронт не затрагивается — postbuild-автодеплой не нужен.)

## 7. Тестирование

**Юнит (общий хелпер):**
- `rasterize_svg_to_png`: валидный SVG → PNG с корректной сигнатурой (`\x89PNG`), RGBA, ширина=1024.
- `_looks_like_svg`: `<svg…`, `<?xml…><svg>`, SVG с ведущими пробелами/BOM → True; реальный PNG/JPEG → False.

**Гард ② (validator, live-DB style):**
- POST `/upload-image` с SVG → ответ `url` оканчивается на `.png`, скачанный объект — валидный PNG.
- POST с реальным PNG → проходит без изменений.
- Битый SVG → 400.
- `BRAND_SVG_RASTERIZE_ENABLED=0` → SVG принимается как раньше (обратная совместимость).
- Учитывать autouse `engine.dispose` fixture (conftest) для live-DB тестов.

**Воркер ③:**
- Скачанный SVG-логотип → перезаписан валидным PNG до FFmpeg; FFmpeg не падает по PNG-сигнатуре.
- Скачанный PNG → не трогается.

**Скрипт ① (smoke на dev-БД):**
- `--dry-run` ничего не меняет, корректно перечисляет 79/113.
- Боевой прогон на тестовом проекте: `logo_url` стал `.png`, объект — валидный PNG, застрявшие задачи → `pending`.
