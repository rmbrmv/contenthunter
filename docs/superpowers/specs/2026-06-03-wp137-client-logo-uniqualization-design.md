## 1. Задача

Внутри клиентской «Уникализации» появляется новый **Шаг 1/2 — выбор уникализированных вариантов лого** перед существующим выбором схем (он становится Шагом 2/2).

Берём загруженный лого клиента (обрезанный, с прозрачным фоном — даёт WP#136), прогоняем через генеративную image-модель по промту и выдаём **N вариантов** на выбор (разный фон/оформление, скруглённые углы, прозрачные поля). Клиент галочками выбирает необходимое число для уникализации. Без выбора — переход к схемам заблокирован.

**Зачем:** снять ручной флоу Ани (она руками генерит PNG); защита от shadow-ban (разнообразие лого → меньше детект дубликатов); логически чище для клиента (сначала финальный набор обложек бренда → потом ролики).

### User stories
- **US-1 (клиент):** галочками выбрать нужное число вариантов лого из автогенерированных, чтобы аккаунты выглядели разнообразно.
- **US-2 (владелец продукта, гейт):** запретить переход на Шаг 2 без выбранного набора лого.
- **US-3 (админ):** зайти в распаковку клиента и пройти Шаг 1 за него, чтобы разблокировать застрявший проект.

## 2. Решения по открытым вопросам (утверждено с Данилом)

| Вопрос | Решение |
|---|---|
| **Движок генерации** | Генеративная image-модель (не детерминированная композиция). |
| **Провайдер/модель** | **Laozhang → gpt-image-1** (image-edit: вход = обрезанный лого + промт). Ключ `laozhang_api_key` уже в конфиге. Фолбэк на другой image-эндпоинт того же прокси, если edit недоступен (проверка на этапе реализации). |
| **Когда генерировать (ТЗ Часть A)** | **Сценарий А — по кнопке** «Сгенерировать варианты». Платим только когда клиент реально дошёл. |
| **Сколько выбрать** | **По плану (динамика):** выбрать = `pack_count` (число паков, как `min_required` у схем). |
| **Сколько генерировать** | **`pack_count + 5`** (запас, чтобы было из чего выбрать). |
| **Fallback если паков нет** (`pack_count = 0`) | выбрать = 5, сгенерировать = 10 (числа из исходного ТЗ). |
| **Где разместить** | **Шаг 1/2 в существующем мастере `SchemesPage.vue`** (видео/лого/схемы). Соответствует «Шаг 1/2 → Шаг 2/2». |
| **Reuse грида схем vs дублировать** | **Дублировать** — отдельный лёгкий `LogoVariantCard`. У схем тиндер/approve-reject, у лого — мульти-выбор чекбоксами; разные модели взаимодействия. |
| **Исполнение генерации** | В **backend** (async-задача) — это лёгкие HTTP-вызовы к Laozhang, не FFmpeg/GPU (в отличие от удалённого воркера превью схем). |

## 3. Модель данных (PostgreSQL `openclaw`)

### `logo_variants` — сгенерированные варианты
| Колонка | Тип | Назначение |
|---|---|---|
| `id` | bigserial PK | |
| `project_id` | int → `validator_projects.id` | клиент |
| `logo_source_hash` | text | sha256 исходного лого (байты/URL) — ключ дедупа |
| `prompt_template_version` | int | версия набора промтов |
| `variant_index` | int | порядковый 0..N-1 |
| `s3_url` | text | PNG 900×900 в S3 |
| `status` | text | `pending`/`done`/`failed` |
| `model_used` | text | напр. `gpt-image-1` |
| `created_at` | timestamptz | |
| `ttl_at` | timestamptz NULL | срок жизни; `NULL` = не истекает (для выбранных) |

Уникальность `(project_id, logo_source_hash, prompt_template_version, variant_index)` — защита от F5/дублей (ТЗ п.6).

### `logo_selections` — выбор клиента
| Колонка | Тип | Назначение |
|---|---|---|
| `id` | bigserial PK | |
| `project_id` | int → `validator_projects.id` | |
| `variant_id` | bigint → `logo_variants.id` | выбранный вариант |
| `selected_at` | timestamptz | |
| `selected_by` | int → `validator_users.id` | клиент или админ (US-3) |

Уникальность `(project_id, variant_id)`.

### Очередь генерации — `unic_tasks`, `task_type='logo_variants'`
Переиспользуем существующую очередь (паттерн `scheme_preview`): хранит статус/прогресс (`done`/`total`), идемпотентность по payload_hash, устойчивость к рестарту. Payload: `{project_id, logo_source_hash, prompt_template_version, total}`.

### Шаг мастера — **не храним отдельно**
Выводим из данных: `COUNT(logo_selections WHERE project_id) >= required` → шаг лого пройден (открываем схемы); иначе открываем шаг лого. Это и реализует «открыть на том шаге, где остановился».

## 4. Бэкенд — роутер `logo_variants.py` (validator/backend)

- `GET /api/logo-variants/readiness?project_id`
  → `{ has_logo, logo_url, required, total_to_generate, generation:{status,done,total}, variants:[{id,variant_index,s3_url,status}], selected_ids:[…] }`
- `POST /api/logo-variants/generate?project_id` — **Сценарий А**.
  Идемпотентно: если варианты для `(project, source_hash, version)` уже есть → no-op (возврат существующих). Иначе enqueue `unic_tasks(logo_variants)`. Kill-switch `LOGO_VARIANTS_GENERATION_ENABLED`.
- `POST /api/logo-variants/select` `{ variant_ids:[…] }`
  Атомарная перезапись `logo_selections` для проекта. Валидация: число = `required`; все `variant_id` принадлежат проекту и `status='done'`. Обнуляет `ttl_at` у выбранных (snippet: `ttl_at = NULL`).
- `POST /api/logo-variants/retry?project_id` — повтор при ошибке (сбрасывает failed-задачу, enqueue заново).
- `POST /api/logo-variants/reset?project_id` — admin/manager: удалить варианты+выборы+S3 (зеркало reset мастера схем).

### Исполнение генерации (backend async)
- Фоновая задача забирает `unic_tasks(logo_variants)`, для каждого `variant_index`:
  1. вызов Laozhang gpt-image-1 (edit: обрезанный лого + промт варианта),
  2. пост-обработка Pillow (см. §5),
  3. upload PNG → S3, INSERT `logo_variants` (инкрементально), `done_count++`.
- Резюмирование: при рестарте/повторном `generate` дозаполняет недостающие `variant_index` (по уникальному ключу).
- Ошибки → лог с `project_id, reason, model_used` (+ Sentry, если подключён). Частичный успех допустим (`status` задачи `partial`), UI показывает что есть + «Повторить».

## 5. Генерация — `services/logo_variant_service.py`

- **Промты:** набор версионированных шаблонов (`LOGO_PROMPT_TEMPLATE_VERSION`) на базе промта Ани, варьируем фон/оформление между вариантами. Базовый промт Ани:
  > Вот логотип, сделай маленькие PNG, разные варианты, меняется фон, скруглённые углы, прозрачный фон вокруг карточки. Без лишнего увеличения. 900×900. Вес 200–500 КБ.
- **Клиент Laozhang:** image-edit gpt-image-1, вход = обрезанный лого (из `logo_url`/WP#136), на выход b64/URL.
- **Пост-обработка (Pillow):** привести к 900×900, скруглить углы → прозрачные поля вокруг подложки, ужать вес в диапазон 200–500 КБ. Гарантирует требования ТЗ независимо от вывода модели.

## 6. Фронтенд — Шаг 1/2 в `SchemesPage.vue`

Новый компонент **`LogoVariantStep.vue`** (+ `LogoVariantCard.vue`). Порядок мастера: **лого (1/2) → схемы (2/2)**; обновить индикатор шагов.

### Структура экрана (сверху вниз, по ТЗ)
- Заголовок «Шаг 1/2 — Выберите уникализированные лого».
- Прогресс-индикатор «● Лого ○ Схемы».
- Блок-объяснение «Зачем выбирать варианты лого?».
- Грид: **5 колонок**, строк = `ceil(total/5)`. Карточка: PNG 900×900 (прозрачный фон), чекбокс в правом верхнем углу, hover scale-1.05 + тень, клик по всей карточке = toggle.
- Счётчик «Выбрано N из `required`»: серый при N<required, зелёный при N=required.
- Кнопка «Далее»: disabled пока N≠required; активна при N=required.

### Состояния
- **Idle (Сценарий А):** объяснение + кнопка «Сгенерировать варианты».
- **Генерация:** `total` skeleton-плейсхолдеров с shimmer + «Готовим варианты лого, 8–15 секунд». Polling `readiness`.
- **Готово:** грид.
- **Ошибка:** error-state + «Повторить». Лог в Sentry (`project_id`, причина, `model_used`).
- **Нет лого (`!has_logo`):** заглушка «Сначала загрузите логотип» + кнопка «Перейти к распаковке» → `BrandPage`.

### Гейт (US-2)
- «Далее» disabled пока выборов ≠ `required`.
- При клике «Далее» — `POST /select` (атомарно), затем переход на Шаг 2.
- Обход по URL на Шаг 2 без выбора → редирект на Шаг 1 + toast «Сначала выберите варианты лого».
- Kill-switch `LOGO_VARIANT_GATE_ENABLED`.

### Возврат Шаг 2 → Шаг 1
- «Назад» возвращает на Шаг 1, текущие галочки сохранены (из `logo_selections`). Перевыбор → повторный `/select` перезаписывает атомарно.

## 7. TTL / cron
Суточный крон удаляет `logo_variants` где `ttl_at < now()` И вариант не в `logo_selections`. Выбранные не удаляются (`ttl_at = NULL`). При генерации новые варианты получают `ttl_at = now() + 30 days`.

## 9. Тестирование (TDD)
- backend: дедуп `generate` (повторный вызов = no-op), идемпотентность по уникальному ключу; `select` валидация (число = `required`, чужой `variant_id` отклоняется, не-`done` отклоняется); `required`/`total_to_generate` от `pack_count` (+5; fallback 5/10); reset; kill-switches off → 503/no-op; обнуление `ttl_at` у выбранных.
- генерация: пост-обработка Pillow (900×900, прозрачные углы, вес 200–500 КБ); фолбэк при недоступности edit-эндпоинта; частичный успех.
- TTL cron: удаляет истёкшие невыбранные, не трогает выбранные.
- frontend: гейт «Далее», счётчик серый/зелёный, no-logo заглушка, polling, error-state.
