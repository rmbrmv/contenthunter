# WP#136 — Лого клиента: кроп в квадрат 1:1 + ML-удаление фона

**OpenProject:** Content Hunter WP#136 «Лого клиента (подогнать под наши параметры)»
**Статус:** В разработке · **Assignee:** Данил · **Дата:** 2026-06-01
**Ветка:** `wp136-client-logo-crop`

## Проблема

Уникализация требует квадратное лого (1:1) с прозрачным фоном. Сейчас клиент в распаковке
может загрузить прямоугольное лого, и при сборке видео `unic-worker/worker.py` (~366-372)
форсит его в квадрат фильтром `scale={ls}:{ls}` — лого **сплющивается** и выглядит некрасиво.

## Цель

При загрузке лого в распаковке клиент кропает его в квадрат 1:1 с прозрачным фоном
(инструмент в стиле загрузки аватара в Telegram), опционально убирает фон нейросетью.
На выходе всегда **PNG 1024×1024 RGBA с прозрачным фоном**, который без искажений идёт
в уникализацию.

## Решения (согласовано с Данилом 2026-06-01)

- **Удаление фона:** полноценное ML (rembg / U2Net), вынесено **отдельным микросервисом
  на сервер уникализации `91.98.180.103`** (рядом с `unic-worker`), не на валидатор-бокс.
- **Логика кропа по умолчанию:** вписать лого целиком (fit, прозрачные поля по бокам),
  ничего не теряем; зум для врезки — опционален. (Лого нельзя обрезать как аватар —
  отрезанный элемент = брак.)
- **Момент удаления фона:** сразу по клику чекбокса — живой превью в окне кропа.
- **Архитектура:** вариант A — тонкий прокси на бэкенде + кроп на фронте (Canvas).
  Финальный 1:1 PNG формирует браузер (`canvas.toBlob`).

## Архитектура

```
Клиент (BrandPage.vue)
  │ выбирает файл лого
  ▼
[detect] квадрат (w==h) И есть реальная прозрачность?
  ├─ да ──────────────► загрузка как есть (/api/brand/upload-image) — кроп пропущен
  └─ нет ─► открыть <LogoCropModal>
              ├─ canvas: лого вписано в квадрат (fit), зум-ползунок, drag
              ├─ ☐ «удалить фон» → POST /api/brand/remove-bg ──┐ (живой превью)
              └─ «Готово» → canvas.toBlob(1:1 PNG) ──► /api/brand/upload-image
                                                                 │
   валидатор-бэк (72.56.107.157:8000) ◄──── проксирует ──────────┘
              │  + X-Internal-Token, таймаут ~15с, kill-switch
              ▼
   rembg-микросервис (91.98.180.103:8077, FastAPI + rembg/onnxruntime CPU)
              POST /remove-bg  (PNG in → transparent PNG out)
```

Затрагиваемые репозитории:
- `validator-contenthunter/frontend` — новый компонент `LogoCropModal.vue` + интеграция в `BrandPage.vue`.
- `validator-contenthunter/backend` — новый прокси-эндпоинт в `routers/brand.py`.
- **Новый сервис** `/root/logo-bg-service` на `91.98.180.103` (rembg HTTP).

## Компоненты

### 1. Frontend — `LogoCropModal.vue` (новый)

- Открывается из `BrandPage.vue` после выбора файла **только для поля логотипа**
  (pattern и прочие image-поля не трогаем).
- **Detect-skip** до открытия модалки: загружаем файл в `Image`/canvas; если
  `naturalWidth === naturalHeight` И в alpha-канале есть прозрачные пиксели
  (семпл по краям/сетке) → модалку не показываем, грузим файл как есть.
- В модалке:
  - `<canvas>` с квадратной рамкой-маской; картинка по умолчанию вписана целиком (fit),
    по бокам прозрачно.
  - `<input type="range">` зум (от fit до ~2×).
  - drag мышью/тачем для позиционирования.
- Чекбокс «удалить фон»:
  - включение → спиннер, **оригинал** уходит на `POST /api/brand/remove-bg`;
    ответный transparent PNG подменяет картинку на canvas (позиция и зум сохраняются).
  - снятие галочки → возвращаем оригинал. Оба варианта кэшируем в памяти, чтобы не
    дёргать сервис повторно.
- «Готово»: рисуем текущее состояние на offscreen-canvas **1024×1024** на прозрачном
  фоне → `toBlob('image/png')` → шлём в существующий `/api/brand/upload-image`.
  «Отмена» → состояние поля не меняем.

### 2. Backend — `POST /api/brand/remove-bg` (новый прокси)

Файл: `backend/src/routers/brand.py`.
- Принимает multipart image. Лимит 10 МБ, тот же набор MIME, что у `upload-image`;
  SVG-вход сначала растеризуем существующим `rasterize_svg_to_png`.
- Проксирует на микросервис: `POST {LOGO_BG_REMOVAL_URL}/remove-bg` с заголовком
  `X-Internal-Token: {LOGO_BG_REMOVAL_TOKEN}`, таймаут ~15 с (httpx).
- Возвращает transparent PNG (`image/png`) во фронт, либо понятную ошибку.
- **Kill-switch** `LOGO_BG_REMOVAL_ENABLED`: если выкл — эндпоинт отдаёт 503, фронт
  прячет чекбокс. Это не ломает основной кроп.
- Эндпоинт `upload-image` **не меняем** по контракту — он принимает уже готовый PNG.

### 3. rembg-микросервис (новый, на 91.98.180.103)

- Папка `/root/logo-bg-service` рядом с `unic-worker`; FastAPI + uvicorn; PM2-юнит
  в стиле существующего `ecosystem.config.js`.
- `POST /remove-bg`: проверяет `X-Internal-Token`, принимает image-bytes, прогоняет
  `rembg` (модель `u2net`, onnxruntime CPU), возвращает PNG с alpha. `GET /health`.
- Зависимости: `rembg`, `onnxruntime`, `pillow`, `fastapi`, `uvicorn`, `python-multipart`.
  Модель (~170 МБ) скачивается один раз при первом прогреве.
- **Безопасность:** bind на порт 8077; ufw/firewall — входящие только с `72.56.107.157`;
  обязательный shared-token. Публичный домен не вешаем.
- **Конкурентность:** rembg тяжёлый по CPU — ограничиваем параллелизм (1-2 воркера
  uvicorn или семафор), чтобы не конкурировать с FFmpeg-рендером `unic-worker`.
  Путь синхронный, отдельный от очереди `unic_tasks`.

## Формат вывода и хранение

- Финал всегда: **PNG, ровно 1024×1024, RGBA, прозрачный фон.**
- Кладём в S3 существующим `upload-image`: ключ `brand/{pid}/logo/{uuid}.png`,
  пишем в `validator_brand_profiles.logo_url`.
- Потребитель `unic-worker resolve_logo` (115-140) **не меняется** — ему приходит
  корректный квадрат, `scale={ls}:{ls}` больше не искажает.
- Почему 1024: совпадает с текущей растеризацией SVG, ≥ требования 500×500, запас под оверлей.

## Kill-switches / конфиг

- `LOGO_BG_REMOVAL_ENABLED` (backend, default off до прогрева сервиса).
- `LOGO_BG_REMOVAL_URL` (например `http://91.98.180.103:8077`).
- `LOGO_BG_REMOVAL_TOKEN` (shared secret).
- Существующий `BRAND_SVG_RASTERIZE_ENABLED` остаётся как есть.

## Обработка ошибок

- Микросервис недоступен/таймаут → бэк отдаёт 502/503; фронт показывает
  «не удалось убрать фон, попробуйте позже» и **продолжает кроп без удаления фона**.
- Кроп никогда не блокируется ML-частью — удаление фона строго опционально.
- Невалидный/битый файл → стандартная 400 (как у `upload-image`).

## Тестирование

- **Backend:** pytest на прокси — happy-path (mock микросервиса), таймаут/недоступность,
  выключенный `LOGO_BG_REMOVAL_ENABLED` → 503, SVG-вход растеризуется до проксирования.
- **Микросервис:** `GET /health`; `POST /remove-bg` на фикстуре (квадрат с заливкой →
  в выводе появился alpha); проверка токена (401 без него).
- **Frontend:** unit на detect-skip (квадрат+прозрачность → skip; прямоугольник → модалка);
  ручная проверка модалки (fit-по-умолчанию, зум, drag, чекбокс, экспорт 1024×1024).

## Вне scope (YAGNI)

- Кроп/обработка прочих image-полей бренда (паттерн и т.п.) — только логотип.
- Пакетная переобработка уже загруженных лого — не трогаем существующие записи.
- Замена FFmpeg-логики наложения лого в `unic-worker` — контракт потребителя не меняется.
- Очередь/асинхронность для удаления фона — путь синхронный, по требованию живого превью.
