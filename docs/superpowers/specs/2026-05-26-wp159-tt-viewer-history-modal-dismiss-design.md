# WP #159 — TikTok: авто-закрытие модалки «История просмотров» на профиль-табе

**Дата:** 2026-05-26
**Родитель:** WP #131 (TT `tt_profile_tab_broken`, разведка 2026-05-26)
**Репозиторий кода:** `GenGo2/delivery-contenthunter` (autowarm), прод-путь `/root/.openclaw/workspace-genri/autowarm/account_switcher.py`
**Категория:** A (ясный спек, низкий риск, ограниченный объём)

## Проблема

При переключении TikTok-аккаунта на профиль-табе всплывает нижняя шторка-consent
«История просмотров включена». Бот не распознаёт под ней собственный профиль,
исчерпывает 3 retap'а и падает `_fail(tt_2_not_own_profile)` → `tt_profile_tab_broken`.

**Воспроизведение:** task 9648, аккаунт `komilfo_vibe`, устройство `RF8Y80ZV1WF`, 25.05.
Длиннохвостый кейс (1 из 5 свежих падений категории), не блокер.

### Содержимое модалки (UI-дамп task 9648, `tt_2_profile_tab`)

| Элемент | class | clickable | примечание |
|---|---|---|---|
| контейнер | FrameLayout | — | `content-desc="Нижняя шторка"` `[0,497][1080,2205]` |
| заголовок | (obf) | нет | text=`История просмотров включена` |
| тело | TextView | — | «Другие пользователи увидят, что вы просматривали их профили…» |
| строка-тоггл | TextView | нет | text=`История просмотров` |
| тоггл | Switch | да | `checked=true` (ВКЛ по умолчанию), без текста `[854,1790][990,1867]` |
| **кнопка** | Button | **да** | text=`Сохранить` `[90,1980][990,2126]` |
| крестик | Button | да | **без текста** `[945,508][1058,632]` (только координаты) |

Ключевое отличие от уже покрытых промо (контакты/Facebook, WP #106): здесь **нет
кнопки отказа** («Не разрешать»). Единственная текстовая кнопка — `Сохранить`
(affirmative). Крестик-закрытие без текста → недоступен текстовому матчингу.

## Решение

Переиспользовать существующий механизм WP #106 / WP #67 Layer 2 **без новой логики** —
добавить модалку в вайтлист авто-закрываемых промо на профиль-табе.

### Изменения (все в `account_switcher.py`)

**1. Вайтлист `_TT_PROFILE_PROMO_DISMISSIBLE_MODALS` (~строка 370)** — одна запись:

```python
('История просмотров', 'Сохранить'),  # [WP #159] task 9648 — viewer-history consent
```

- `title_substr='История просмотров'` — подстрока заголовка `История просмотров включена`
  и лейбла тоггла `История просмотров`. Матч в `_tt_try_dismiss_profile_promo`
  дополнительно требует clickable-кнопку с точным текстом → ложноположительные на
  чистом профиле исключены (на профиль-табе этой строки нет, и кнопки `Сохранить` нет).
- `button='Сохранить'` — единственная текстовая кнопка; тап по **тексту** через
  `tap_element`, device-agnostic (в отличие от координат крестика).

**2. Поведение при закрытии — без изменений кода.** Тап `Сохранить` (тоггл ВКЛ по
умолчанию) подтверждает настройку и закрывает шторку навсегда (повторно не всплывает).
Caller (`_switch_tiktok` retap-loop, ~строка 2831) уже делает `sleep` + re-dump +
`_tt_is_own_profile` на следующей итерации → попадаем на профиль.

**Сторонний эффект:** на аккаунте подтверждается «История просмотров = ВКЛ». Для
бот-аккаунтов безобидно (и поведенчески «человечнее»); решение согласовано с владельцем
(Данил, 2026-05-26). Альтернативы (крестик по координатам / выкл-тоггл-then-save /
system BACK) отклонены как device-fragile или рискующие увести с профиль-таба.

**3. Никаких новых** методов, `error_code`, событий, изменений схемы БД/API. Метод
`_tt_dismiss_profile_promo_dialog` и событие `tt_profile_promo_dismiss_attempted`
переиспользуются как есть.

**4. Kill-switch** — существующий `TT_PROFILE_PROMO_DISMISS_DISABLED=1` покрывает и
эту запись (defensive отключение всего профиль-промо-dismiss без редеплоя).

  не ломает; имя теста оставить как есть, чтобы не плодить переименований в diff.)
- **Интеграционный** (по образцу `test_retap1_promo_dismissed_then_own_profile`):

- **Негативный** (опц.): дамп с заголовком `История просмотров`, но кнопкой не
  `Сохранить` (или не clickable) → `None` (защита от ложного dismiss).
- Полный прогон `pytest tests/test_account_switcher_profile_promo_dismiss.py` зелёный,
  регресс существующих тестов не нарушен.
