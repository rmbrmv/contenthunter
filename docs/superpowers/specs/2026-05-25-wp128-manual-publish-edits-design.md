## Контекст

Подраздел «Ручная выкладка» — одна таблица паков (группировка по `unic_result_id`), которую видят и операторы, и админы. Рендер — `mpqRender()` (полный `innerHTML` для `thead`+`tbody`), опрос — `mpqPoll()` каждые 5 с с **полным** ререндером таблицы и открытой карточки. Видео встроено `<video>` в карточку пака. Источник данных — `GET /api/publishing/manual-queue` → `manual_publish_queue.js: listQueue → rowToDict`.

Статусы пака (`agg_status`, агрегат из строк-платформ): `queued` «В очереди», `in_progress` «В работе», `partial` «Частично выложено», `published` «Выложено».

WP содержит 6 правок; решения по неоднозначным пунктам зафиксированы на уточнении с Данилом:

- **П.3 «дата перевода … чтобы старые видео не падали в список»** → трактуем как **информативную колонку без фильтра**. П.3 и п.5 — это **одна и та же** колонка «Ручная дата» (= `created_at`), просто описана с точки зрения админа и оператора.
- **П.1 чекбоксы фильтра по статусам** → размещаем **в шапке колонки «Статус»** (на месте текущего `<select>`).
- **П.2 точечное обновление** → поллинг **патчит статусы И добавляет/убирает строки** при изменениях, но **не перерисовывает неизменившиеся ячейки**.

## Изменения

### R1 — Чекбоксы фильтра по статусам (в шапке колонки «Статус»)

- **Состояние:** `mpqFilters.agg_status` становится **массивом** выбранных статусов вместо строки. Инициализация по умолчанию — `['queued','in_progress']` (там, где объявлен `mpqFilters`; **не** сбрасывать на каждом поллинге).
- **`mpqMatch()` (12091):** добавить ветку для `agg_status`: если фильтр — массив, делегировать в чистую `mpqStatusVisible(card.agg_status, массив)` (см. «Тестируемое ядро») — показывать пак iff `card.agg_status ∈ массив`. Пустой массив → показывать пусто (предсказуемо; по умолчанию отмечены 2 пункта). Прочие колонки — без изменений.
- **`mpqFilterCell()` (12104):** для `c.key === 'agg_status'` рендерить компактную группу из 4 чекбоксов (В очереди / В работе / Частично выложено / Выложено) вместо `<select>`. `onchange` каждого тогглит членство в `mpqFilters.agg_status` и вызывает **ререндер только тела** (см. R2: `mpqRenderBody()`), чтобы не терять фокус/состояние чекбоксов и не дёргать шапку.
- **Прочие фильтры (select/date/text, 12110/12113/12115):** их `onchange`/`oninput` тоже перевести с полного `mpqRender()` на `mpqRenderBody()` — шапку при смене фильтра перерисовывать незачем, а для R6 это убирает лишний ребилд `thead`.
- **`mpqReset()` (12178):** сбрасывать `agg_status` обратно к дефолту `['queued','in_progress']`, а не к `{}`.

### R2 — Убрать видео из карточки + точечное обновление

**(a) Видео.** В `mpqRenderCard()` удалить элемент `<video>` (строка 12252). Ссылки «⬇ исходное» / «⬇ уник.» (12254–12257) **оставить** — это и есть «только ссылка».

**(b) Точечное обновление вместо полного ререндера.**

Разбить `mpqRender()` на `mpqRenderHead()` (thead: заголовки + ячейки фильтра, 12149–12152) и `mpqRenderBody()` (tbody: группы по телефону + строки, 12153–12162). Полная загрузка/сортировка/сброс/смена фильтра вызывают нужную часть; поллинг — новую `mpqReconcile()`.

`mpqReconcile()` (вызывается из `mpqPoll()` вместо `mpqRender()`):
- `newCards = mpqApply()`; индекс `newByUnic`.
- Каждой строке данных проставлять `data-mpq-unic`; заголовку группы — `data-mpq-phone`.
- **Удаление:** DOM-строки, чьего `unic_result_id` нет в `newByUnic`, удалить; опустевшие заголовки групп удалить.
- **Патч (in-place):** для выживших строк сравнить статус-производные данные и при изменении переписать **только** ячейки: «Платформы» (12138, метки ✓/⏳), «Статус» (12141), «Действие» (12142, `mpqCardActions`). Статичные ячейки (телефон/проект/пак/видео-ссылки/план-дата/ручная-дата) **не трогать**.
- **Добавление:** новые `unic` вставить в свою группу (создать заголовок группы при отсутствии) в правильную позицию сортировки внутри группы; обновить счётчик `(N)` в заголовке.
- Тоггл `#mpq-empty` по `newCards.length`.
- **Порядок строк:** при дефолтной сортировке (`planned_date`, `phone_number`, `id`) смена статуса не меняет порядок → точечный патч безопасен. Если оператор сортирует по меняющемуся полю (напр. «Статус»), смена статуса переставит строки — `mpqReconcile` сверяет желаемый сгруппированный порядок с DOM и при расхождении делает полный пересбор тела (иначе осталась бы устаревшая сортировка).

Карточка (если открыта) — `mpqReconcileCard()` вместо `mpqRenderCard()` в `mpqPoll()` (12313):
- Каждой строке-платформе (`mpqPlatformRowHtml`, 12202) проставить `data-mpq-row="<id>"`.
- На поллинге патчить по id только: статус платформы, ячейку ссылки-публикации, кнопки действий; и агрегат-статус в шапке карточки. Заголовок/описание/хэштеги/ссылки — не трогать (видео уже удалено).
- Сохранить гард `mpqCardHasUnsavedInput()` (12302) — не перетирать, пока оператор печатает URL.

**Kill-switch:** `window.MPQ_TARGETED_REFRESH` (по умолчанию `true`). При `false` — `mpqPoll()` откатывается на старый полный `mpqRender()`+`mpqRenderCard()`. Видео-удаление (a) — без флага (мелкое, безопасное).

**Тестируемое ядро (чистые функции, без DOM):**
- `mpqStatusVisible(aggStatus, checkedArray)` — предикат R1.
- `mpqDiff(currentKeys, desiredCards)` → `{toRemove, toAdd, toPatch}` поверх простых данных (ключи + статус-сигнатура). DOM-применение — тонкая обёртка над результатом.

### R3 + R5 — Колонка «Ручная дата» (информативная)

- **Бэкенд `manual_publish_queue.js`:** в `JOINED_SELECT` добавить `to_char(q.created_at, 'YYYY-MM-DD') AS manual_date`; в `rowToDict` пробросить `manual_date: m.manual_date`.
- **Фронт:** в `MPQ_COLS` (12038) вставить `{ key: 'manual_date', label: 'Ручная дата', filter: null }` **сразу после** `planned_date` (12045). В `mpqCardRowHtml` (12129) добавить ячейку `<td>${esc(card.manual_date ?? '')}</td>` после ячейки план-даты (12140). В `mpqCards()` (12064) пробросить `manual_date` в объект пака (берётся из первой строки). Фильтр не добавляем.

### R4 — Убрать «План выкладки» из сайдбара

- Удалить кнопку `nav('validator-plan')` (строка 279). Секцию `section-validator-plan` и запись в `sidebarMap` оставляем нетронутыми (безвредны, обратимо одной строкой).

### R6 — Дёргание ширины колонки статуса

- **Причина:** `#mpq-table` — auto-layout, у колонки статуса нет фиксированной ширины. Любой ререндер, где появляется/исчезает длинная метка «Частично выложено», пересчитывает ширину; `onchange` дейтпикера «План дата» (12113) дёргает `mpqRender()`.
- **Фикс:** `table-layout: fixed` на `#mpq-table` + явные `width`/`min-width` на `<th>`/ячейках колонки статуса, рассчитанные под самую длинную метку **и** под чекбоксы R1. Ширина стабильна при смене фильтров и ререндерах.
- R2 (уход от полного ререндера на поллинге) дополнительно снижает реальные перерисовки, но дейтпикер — действие пользователя, поэтому фикс ширины обязателен независимо.

## Тестирование

- **Бэкенд (node `--test`, `test_manual_publish_queue.test.js`):** тест, что `rowToDict` пробрасывает `manual_date` из строки.
- **Фронт (node `--test`):** юнит-тесты чистого ядра — `mpqStatusVisible` (дефолт показывает queued+in_progress, скрывает partial/published; пустой набор → пусто) и `mpqDiff` (корректные `toRemove/toAdd/toPatch` при появлении/исчезновении пака и смене статуса). Для этого вынести обе функции в отдельный модуль (стиль `client_manual_filter.js`), а `index.html` подключает/инлайнит логику.
- **Ручная приёмка** на тестовой копии (паттерн `cp` в тест → cherry-pick в прод-main): (1) по умолчанию видны только «В очереди»+«В работе»; (2) видео в карточке нет, ссылка «⬇ уник.» осталась; (3) статусы обновляются вживую без морганий и без прыжка прочих полей; (4) появление/исчезновение пака при смене фильтра/статуса; (5) ширина колонки статуса стабильна при смене даты в «План дата»; (6) колонка «Ручная дата» стоит после «План дата»; (7) пункта «План выкладки» в сайдбаре нет.

## Деплой и откат

- **Изоляция:** реализация в **отдельном worktree** от `autowarm` `main` (никогда напрямую в прод `main` — там auto-push hook на `GenGo2/delivery-contenthunter`). PR в `GenGo2/delivery-contenthunter` (токен `~/secrets/github-gengo2.env`).
- **Деплой фронта:** `public/index.html` живёт в прод-чекауте; тест-деплой через `cp`, постоянный — cherry-pick в прод `main` (auto-push hook доставляет). Бэкенд-строка SELECT требует рестарта процесса автоварма, обслуживающего `/api/publishing/manual-queue`.
- **Kill-switch:** `window.MPQ_TARGETED_REFRESH=false` мгновенно возвращает старый полный ререндер без релиза.
- **Откат:** все изменения декларативны и обратимы через git; колонка/кнопка/чекбоксы — точечные правки `public/index.html`, бэкенд — одна строка SELECT.

## Риски

- **Главный риск — `mpqReconcile()`** (корректность DOM-диффа: заголовки групп, позиция вставки, синхронизация счётчиков). Снижение: чистая `mpqDiff` под юнит-тестами + kill-switch на полный ререндер.
- Чекбоксы в узкой колонке статуса — следить, чтобы не растягивали колонку; решается фиксированной шириной (R6).
- Смена дефолта фильтра (раньше показывались все статусы, теперь только queued+in_progress) — ожидаемое поведение по ТЗ; операторы увидят меньше строк по умолчанию.
